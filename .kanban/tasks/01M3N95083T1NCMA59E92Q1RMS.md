## What

`TelemetryCapture` keeps the label of the logger that writes each log record. Now the capture log handler drops the label.

## Why

Two packages must check the logger label of a record:
- FoundationModelsMetadataRegistry: its test now checks the label on `RegistryTelemetry.makeLogger()`, not on each record.
- FoundationModelsACPAgent: the criterion of its OTel 3 task, "label FoundationModelsACPAgent.PromptTurn", cannot be checked through the capture.

Rule 3 of the OpenTelemetry design says that each package has names with the module name as a prefix. The label is part of this vocabulary, so the tests must see it.

## Files

- `Tests/TelemetryTestSupport/TelemetryLogRouting.swift`: the log handler keeps the label that the factory gets, and writes it on each record.
- `Tests/TelemetryTestSupport/TelemetryCapture.swift`: the captured log record type gets a public `label` property.
- The Extras tests of `TelemetryCapture`.

## Acceptance criteria

- [ ] Each captured log record has the label of the logger that wrote it.
- [ ] The public API of `TelemetryCapture` that is there now does not change. Only the new `label` property is added.
- [ ] The CHANGELOG records the change.

## Tests

- [ ] A test writes with two loggers that have different labels in one capture. It reads back the correct label on each record.
- [ ] Run `swift test`. All tests pass.
