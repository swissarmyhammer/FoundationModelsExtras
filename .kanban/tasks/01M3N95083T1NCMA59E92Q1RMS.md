title: 'OTel F: TelemetryCapture keeps the logger label on each log record'

## What

`TelemetryCapture` keeps the label of the logger that writes each log record. Now the capture log handler drops the label.

## Why

Two packages must check the logger label of a record:
- FoundationModelsMetadataRegistry: its test now checks the label on `RegistryTelemetry.makeLogger()`, not on each record.
- FoundationModelsACPAgent: the criterion of its OTel 3 task, "label FoundationModelsACPAgent.PromptTurn", cannot be checked through the capture.

Rule 3 of the OpenTelemetry design says that each package has names with the module name as a prefix. The label is part of this vocabulary, so the tests must see it.

## Decision (2026-09-30, option A)

swift-log `InMemoryLogHandler.Entry` cannot hold a label. The user chose option A: `TelemetryCapture.Context.logRecords` changes its element type to a new public struct `TelemetryCapture.LogRecord` with `level`, `message`, `error`, `metadata` and `label`. This is a breaking change to the public API of `TelemetryCapture`. Code that reads `.level`, `.message`, `.error`, `.metadata` or compares records keeps its meaning. Code that names `InMemoryLogHandler.Entry` must change. FoundationModelsMultitool and FoundationModelsRouter tests name it; those packages get follow-up tasks.

## Files

- `Tests/TelemetryTestSupport/TelemetryLogRouting.swift`: the log handler keeps the label that the factory gets, and writes it on each record.
- `Tests/TelemetryTestSupport/TelemetryCapture.swift`: new public struct `TelemetryCapture.LogRecord` (`level`, `message`, `error`, `metadata`, `label`; `Equatable`, `Sendable`); `logRecords` gives `[TelemetryCapture.LogRecord]`.
- Other TelemetryTestSupport code that reads the records (for example the content-safety helper).
- The Extras tests of `TelemetryCapture`.

## Acceptance criteria

- [x] Each captured log record has the label of the logger that wrote it.
- [x] `logRecords` gives `[TelemetryCapture.LogRecord]`. The other public API of `TelemetryCapture` does not change.
- [x] The CHANGELOG records the change as breaking, and names the migration from `InMemoryLogHandler.Entry` to `TelemetryCapture.LogRecord`.
