## What

`GenerationQueue` (`Sources/FoundationModelsExtras/ModelPool/GenerationQueue.swift`) is the work queue of each model and also the admission queue of the pool. It records no metric. It does not separate the wait time from the run time, and it does not know its name or its model.

Change:
- `GenerationQueue.init` takes an internal `QueueTelemetry` (from the shared recorder task `w9g6hm8`). Keep `public init()` with the default name `generation`, so that the public API does not break.
- `ModelPool.swift:21` (`Entry.queue`): make the queue with name `model` and `model.ref` = the key of the entry.
- `ModelPool.swift:79` (`admissions`): make the queue with name `admission`, with no model.
- `Job` (`GenerationQueue.swift:151`):
  - make the `QueueTicket` (from `enqueued()`) in `Job.init`, before `enqueue`, so that `run()` never sees a job with no ticket
  - call `started` in `run()` (`:225`) before the detached task runs `body`
  - call `completed` in `finish(result:)` (`:245`). The outcome: a value gives `succeeded`; a `CancellationError` gives `cancelled`; each other error gives `failed`
  - call `completed(…, .cancelled)` in `cancel()` (`:205`) for a job in `.waiting`
  - make sure that each job calls `completed` exactly one time, under the same state lock that makes exactly one path resume the submitter
- Do not change the lock order that `GenerationQueue.swift:16-19` documents. Record the metrics outside the `unfinished` lock.
- Note: the metrics of a job are recorded from the detached task of `run()`. They reach the factory of the submitter because the `QueueTicket` keeps the factory of `enqueued()` (task `w9g6hm8`).

## Acceptance Criteria

- [ ] Each completed job records `queue.wait`, `queue.run` and `queue.tasks` with `queue.name` = `model` (with `model.ref`) or `admission`.
- [ ] `queue.depth` goes up for each job that waits or runs, and goes back to 0 when the queue is idle.
- [ ] `finish(result:)` maps a value to `succeeded`, a `CancellationError` to `cancelled`, and each other error to `failed`.
- [ ] A job cancelled before start records `cancelled` and no run time. A job cancelled while it runs records its run time and `cancelled` when the body throws `CancellationError`.
- [ ] `Job.init` makes the `QueueTicket`. `run()` never sees a job with no ticket.
- [ ] The existing order tests of `GenerationQueue` and `ModelPool` still pass.
