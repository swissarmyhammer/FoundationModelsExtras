title: A tool can end a run as failed and give a value
---
A tool must be able to return its output text and also end the run as failed with a value, for example a shell exit code.

Today only a thrown error gives OperationOutcome.failed. ToolRun.outcomeAndDetail and ContextBindingTool.recordedOutcome give succeeded for any returned string. A thrown error is not good for this use: the model session then sees a tool failure and not the output text.

Proposed shape (no change to OperationOutcome, no change to a tool Output type):
- ToolContext gets a call, for example `reportFailure(value: OperationValue)`. The tool calls it, then returns its output text as usual.
- ToolCallState keeps the reported failure.
- ToolRun.settle and ContextBindingTool.settle read it: the outcome is .failed, the detail stays the output text.
- OperationEvent gets a new optional field `value` (default nil), so the change is additive. The value type is a small Codable Sendable enum: int, string, bool, or a JSON object. An exit code is `.int(n)`.
- A stop, a timeout and a cancel still win over a reported failure.

Acceptance: a test where a tool returns output and reports failed with an exit code; the terminal event has outcome failed, the output as detail and the exit code as value; the model-facing return is unchanged; a tool that does not report gives the same events as before.
