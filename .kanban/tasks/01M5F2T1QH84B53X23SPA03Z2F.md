## What to build

`InMemorySessionDirectory` in Sources/FoundationModelsExtras/Sessions/, in the existing core library target (no test-support product, D73). Its doc comment marks it as a test double. It conforms to `SessionDirectory` and holds sessions, tags, titles and messages in memory.

- **Start:** a fake launcher option gives a list of known agent ids; an unknown id throws `unknownAgent` with near names; nil agent and nil folder resolve as session.md section 6 says.
- **Delivery (10.2):** idle target → `delivered`; working / needsInput → `queued`; archived → `refused` with reason "archived"; agent address with no live root → `started` (origin `.message`); folder with no match → `refused`. `inbox(markRead: true)` marks messages read.
- **Loop guards (10.3), configurable with these defaults:** chain depth 3 (above it → `refused`), message length 16 KB (→ `messageTooLong`), 8 targets per tag send (the rest `refused`), 16 sends per turn. A tag send skips the sender.
- **Archive (ROUTER-11):** sets state `archived`, the session takes no message, sends `archived`.
- **Events (section 7):** each `events()` call is a new `AsyncStream` with `.bufferingNewest(256)`; `started` before the first `stateChanged` of a session; `factsChanged` on tags and title; `messageDelivered` on delivery.
- Test hooks to drive state (for example set a session working / idle with a last summary), so consumers can test `queued` and `stateChanged`.
