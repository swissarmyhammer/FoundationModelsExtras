Found while doing EXTRAS-11 (^q6n4d4x). Rule 9 of EXTRAS-9 asks that the event of `changes` has `added: [ID!]!`, `changed: [ID!]!` and `removed: [ID!]!`, and the doc of `IDChange` (Sources/FoundationModelsExtras/GraphQL/IDChange.swift) says it gives that shape. But `IDChange.added`/`changed`/`removed` are `[String]`, and Graphiti has no `ID` type, so `Type(IDChange.self, as: "NoteChange") { Field("added", at: \.added) … }` gives `added: [String!]!` in the SDL. `GraphQLEndpointConformance.problems` now reports this as `rule 9: The event NoteChange of changes has no field added: [ID!]!.` (and the same for changed and removed).

## Constraint (from the Multitool coordinator)

Two packages already register their own scalar named `ID`: Kanban's `NodeID`, which parses forgiving input (`^short`, type/id, slugs) and must keep doing so, and Skills, which has a copy of that pattern and will delete it once this lands. A second type named `ID` breaks their schemas. So:

- **`addToolkitScalars()` does NOT change.** It still adds only `DateTime` and `JSON`.
- Add a separate opt-in builder method **`addToolkitIDScalar()`** that registers the toolkit `ID` scalar. A package with its own `ID` scalar does not call it and keeps building with no change.

## Work
- Add a toolkit Swift type for an id (for example `GraphQLID`, a `Codable`, `Hashable`, `Sendable` string wrapper that is `ExpressibleByStringLiteral`) and `addToolkitIDScalar()`, which maps it as the scalar `ID` and accepts String and Int input as the GraphQL spec says for ID.
- Make the fields of `IDChange` map to `[ID!]!` through it. Write in the doc comments of `IDChange` and `addToolkitIDScalar()` that an endpoint mapping `IDChange` calls `addToolkitIDScalar()`.
- `ExampleGraph` calls `addToolkitIDScalar()`. Remove the rule 9 exception of `ExampleGraph` in GraphQLTestKitTests `exampleEndpointConforms`, which names this task.

## Acceptance criteria
- [x] The SDL of a `<Noun>Change` built from `IDChange` has `added: [ID!]!`, `changed: [ID!]!`, `removed: [ID!]!`.
- [x] `addToolkitScalars()` does not add `ID`; a test shows that a schema with its own scalar named `ID` plus `addToolkitScalars()` still builds.
- [x] `ExampleGraph` passes `GraphQLEndpointConformance.problems` with no exception.
