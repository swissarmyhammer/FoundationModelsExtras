title: ToolContext tells the run that holds it, so a host can group the inner calls of one run

## What

Make `ToolContext.holdingRunToken` public, with a doc. A host (Multitool `MCPServer`) must know if two tool contexts belong to one run. Each inner `tools.*` call of one `runCode` snippet has its own `completionToken`, so `completionToken` cannot tell that the calls come from one snippet.

- Name and type: `public var holdingRunToken: String` (the name that the package uses now, and the value that `OpenElicitation.runToken` gives for each question of the context).
- The value is the same for the context of a run and for each synchronous inner call that the run mounts, also when the inner calls are nested.
- Two runs give different values.
- A background inner call is a run of its own: its value is its own `completionToken`.
- A context that a host makes with the public init gives its own `completionToken`.
- Additive change. No other change.

## Acceptance Criteria

- [x] Two synchronous inner calls of one run give the same value, and that value is the completion token of the run. Their completion tokens are different.
- [x] A synchronous call nested in an inner call gives the same value.
- [x] Two runs give different values.
- [x] A background inner call gives its own completion token.
- [x] The test file uses a plain import, so it shows that the member is public.

## Tests

Fixed-order Swift Testing tests. No clock, sleep, poll, retry or time limit.
