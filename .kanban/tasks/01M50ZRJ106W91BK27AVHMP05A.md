title: The run plane posts the end of each question that it cancels, in order with the events of the run
---
A host ends open questions itself when it cancels all work or closes. A tool can then complete a question that the host already ended. The end must come from the run plane: the run plane cancels the question and posts the end, in order with the events of the run.

- [x] Add `func post(elicitationEnded elicitationId: ULID, response: ElicitationResponse) async` to `OperationEventSink`, with an empty default. `RunEventFunnel` and `MountedRunUpstreamSink` forward it in order with the events of the run.
- [x] Each question keeps its posting task and an `ending` closure. `ToolContext.elicit` gives `ending: { await sink.post(elicitationEnded: id, response: $0) }`.
- [x] The cancel of questions is async. In one actor step it removes the questions and adds their ids to the ending list. Then, for each question in the order they came: wait for its posting task, await `ending(response)`, remove the id, and resume the run with the cancel.
- [x] `cancel(completionToken:)` and `sweep()` await these end posts before each canceler. After the posts they find the run again, because the run can settle while the posts are in progress.
- [x] Add `public func cancelOpenElicitations() async -> [ULID]` and `public func endingElicitations() -> [ULID]` to `RunPlane`.
- [x] A complete or a respond before the cancel step wins, and no end is posted. After the step, they give `.noPendingElicitation`.
- [x] Doc comments state each order rule and the rule that a sink must not await a cancel of the run plane inside a post.
- [x] An error log shows when a sink awaits a cancel of the run plane inside a post: `RunEventFunnel` sets the `SinkPost` task-local mark around each upstream post, and `cancel(completionToken:)`, `sweep()` and `cancelOpenElicitations()` write an error log when the mark is set. They do not stop a debug build, because `Task {}` copies the mark and a false stop is then possible.
- [x] Fixed-order tests for each order rule. They fail on the old code. No clock, sleep, poll, retry or time limit.
- [ ] One full test run. The change is additive. Push when green, and report the head.
