title: Show a question whose completion post is in progress
---
When an accepted URL flow completes, the run plane takes the question off its list at once, and one task posts the completion and then resumes the run. While that post is in progress, a host cannot tell "a completion is on its way" from "a run cancel ended the question". A cancel of all work or a close in that time can then report a wrong end, and the completion is lost to the host.

- [x] Add `public func completingElicitations() -> [ULID]` to `RunPlane`. It gives the id of each question whose completion post is in progress, in the order of the completes. A question is in this list from the complete until its completion post returns, and then it leaves the list before the run resumes. `openElicitations()` does not change.
- [x] Doc comments: `complete`, `openElicitations()`, `post(elicitationCompleted:)` and the new function state the rule.
- [x] A fixed-order test: a read in the time of the post shows the question in `completingElicitations()` and not in `openElicitations()`; after the post the question is in neither list. The test fails on the old code (the function is new: add it with no behavior first). No clock, sleep, poll, retry or time limit.
- [x] One full test run. The change is additive. Push when green, and report the head.
